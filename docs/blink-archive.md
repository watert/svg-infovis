# blink 路线 · 废弃归档

> **结论**: blink 路线**废弃**。一句话理由: **agent 已有临场开浏览器量尺寸的能力, 不值得为"需要真实渲染尺寸"的场景单独维护一条常驻管线**(HTML 骨架纪律 / CDP 写回 / overlay 叠回 / 结构断言)。本项目旧名 mini-diagram; M2 相关条目整体划掉, 论证留档, 免得将来重推一遍。

## blink 的架构含义

它不是"给 measure 加精度", 而是一个架构决策: **layout 展开器整层外包给浏览器** —— 决策(HTML) → 度量(blink) → 缓存(scene) → 内核(core) → 出口(export), blink 负责把 `getBoundingClientRect` 的真实尺寸写回 scene。

配套的"CSS 路线"笔记是 blink 的**论证源**而非对立方案: 四件事(HTML 骨架禁 left/top → 量 `data-node` 写回 → route 出 SVG overlay → audit 对写回的 scene 跑)与当年的 M2 清单逐条对应。

## 两轴判据(当年为什么认真考虑过它)

- **轴一 · 图有没有必须绕障的边** —— 有就必须量回真实尺寸, 那是 blink 的活; 只需简单直线则 core 整个不必上场
- **轴二 · 交付物是 HTML 源还是 SVG 件** —— HTML 源形态下"量框 + overlay"是加工不是重复劳动; SVG 冻结图形态下为量尺寸先写一遍 HTML 是双份劳动

## 压垮它的实验证据

立项前对 8 张真实图(69 节点 / 55 边)做几何对账:

- **边零穿盒** → 避障压力低, 轴一不成立
- **这批图全是冻结图** → 轴二指向"SVG 进版本库", 为量尺寸先写 HTML 是双份劳动
- **真痛全在排布层**(分层被摊成阶梯 / 组内空白 41–80% / 长边横扫) → 缺口是语义与作者旋钮, 不是像素精度

## 连带处置(摘要)

- M2 全部 blink 条目(组合命令 / 结构断言)整段划掉
- "边表重算缝"关闭: 前提是"度量层会重测尺寸", blink 废弃后该走向不存在; 冻结图坐标烘焙一次, 无重测回路
- `label_fit` 的字体脱钩风险**本身保留为已知边界**: 估宽 vs 观看者字体不随 blink 消失, 解法候选改为"内嵌 woff2 钉字体"

## 复活条件(三条同时出现才重判)

1. 出现**活 HTML 源形态**的图(要交互 / 活主题 / 进 React), 且
2. 图里有**必须绕障的正交边**(轴一成立), 且
3. 临场量尺寸被证明不够用(例如要 CI 可复现的批量管线)

三条缺一条, 本归档继续有效。
