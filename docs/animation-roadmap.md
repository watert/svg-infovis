# 动画路线图(消费面驱动)

> 🕒 更新 260926-18:38 首版。外部对账(可搬什么、为什么) → `docs/animation-parity.md`。
> 本文只回答**往哪走、按什么顺序、哪条线永不越**。数字只进 `QUICKREF.md`, 本文不抄。

## 先摆正:动画的正当理由只有一条

`ROADMAP.md` 的判据是: **动画是装饰性需求还是信息性需求?** 装饰性按「不做投影」同款判词留在外面。
这条判据在三个消费场景下**具体化为同一句**:

> **动效要说明一个有名字的系统行为, 并且停在可读的静帧。**(archify 版判词)

由此推出两条不证自明的纪律:

- **finite + settled**: 一次跑完, 永久回到 authored 静态样式, 不重播。对"golden 是静帧"的仓,
  这条比动画能力本身值钱 —— **静态产物就是动画的末帧**, 所以"动画没做坏这张图"是可以自动验证的
  (见下面「可机器验证的不变量」)。
- **不动语义顺序**: 视觉可以压、可以慢、可以错峰, 但**不能改读者读到的次序**。

## 三个消费场景(要求不同源, 别用一套打)

### 场景 A · 自播交付物(产物 = 一个 `.svg` 文件)

读者在浏览器 / 预览器里打开, 它自己会动, **零 JS**。infograph、看板、报告、vault 里的图都在这档。
**声明式档(SMIL / 内嵌 CSS)在这里是最优解, 不是妥协**: 产物仍是静态字节
⇒ 字节确定 / golden / 禁 `Date.now` 全不受影响, 门禁一行不用动。

### 场景 B · 帧驱动渲染(产物 = 帧序列 → 视频)

宿主每帧问一次"这一刻的画面是什么"。⚠ **声明式档在这里必须关掉**: 帧驱动宿主逐帧截图,
SMIL / CSS 的时钟与帧号**不同步**, 会得到随机帧。这正是 Remotion 禁 CSS 动效的原因,
而**它自己就是那种宿主**。(上一轮"这条禁令不适用我方"的记法要加条件 —— 判据是
**消费侧是不是帧驱动宿主**, 详见对账三第 1 条。)

所以场景 B 只有一条路: **采样档** —— 内核提供纯函数, 宿主在 `t` 处取一个**静态 scene**,
再走现有管线出静态 SVG。

### 场景 C · 交互(产物 = 一个可操作的 HTML / SVG)

`begin="click"` 这类 SMIL 触发、以及 CSS 档 + `:hover` / `:target` 的零 JS 交互。
它与场景 A 同源(交付物都是一份文件), 但**读者从"看"变成"操作"**。
`ExportOptions.hooks`(恒吐 `id` + `data-kind`, 有值才吐 `data-tone` / `data-variant`)就是为这档铺的路。

## 两条腿, 各自长在哪一层(**刻意不共享机制**)

| | 声明式档(场景 A / C) | 采样档(场景 B) |
|---|---|---|
| 作用层 | **descriptor**(属性级) | **scene**(参数级) |
| 形态 | `animate({attributeName, from, to, dur, easing})` | `sceneFn(t) => Scene` |
| 谁来跑 | SVG 自己的时钟(浏览器) | 宿主的帧循环(Remotion 等) |
| 产物 | 一份会动的静态 SVG | 每帧一份静态 SVG |
| 现状 | 地基已落地(`DAnimate` / `DStyle` / `EASING_SPLINES`) | 未做 |

**共享的是真值表(`EASING_SPLINES` / `TIMING`), 不是机制。** 强行把两条腿统一到一套机制上
是最容易犯的错(等于给同一个概念造第二权威, 撞 P4)。它们本来就是同一个坐标系的两个投影:

- 声明式档把"时间"交给渲染器解释;
- 采样档把"时间"在构建期算掉。

**而两者可以互为 oracle**: 采样器在构建期算出的关键帧, 正好是声明式档 `values` 的内容
(这就是 spring 离线烘焙那条路); 声明式档的静态产物, 正好是采样档 `t = 1` 的期望值。

### 采样档几乎不用动内核(这条是重点)

```ts
// 作者写一个纯函数, 内核提供采样契约
const anim = timeline({ durationMs: 800 }, (t) => scene(nodeTween(t), edgeTween(t)));
anim.at(0.5);              // → 普通 Scene, 走现有 exportScene 管线
```

- `t` 的语义由内核**定一处**(建议统一收**毫秒**, 与 `TIMING` 表同单位; 归一化交给场景侧);
- 值插值原语 `tween(from, to, easing)` **读同一份 `EASING_SPLINES`**;
- 求值出来的是**普通 scene** ⇒ `audit` / `exportScene` / auto-fit **一行不改**。

**副产品是本仓独有的一条**: **视频的每一帧都过几何门禁。** 别的视频管线做不到这个 ——
它们的每一帧是像素, 审不了。这条一旦成立, "视频里出现了一条压字体的边"就会在**构建期**被喊,
而不是在成片里被眼睛发现。

## 可机器验证的不变量(建议立项时一并写测试)

- **末帧不动点**: `serialize(sampleAt(1)) === serialize(静态 scene)`。
  这条把"finite + settled"从散文变成断言, 也是"动画没做坏这张图"的自动证据。
- **两条腿同值**: 同一份 `(from, to, dur, easing)`, 声明式档吐的 `keySplines` 与采样档在
  `t = 0.5` 处算出的值必须**由同一条曲线导出**(现在 `EASING_SPLINES` 存的是字符串
  `'0.33 1 0.68 1'`, 采样要把四位数值喂求值器 —— 见下面「待拍板」)。
- **门禁覆盖**: 一帧里的 `audit` 结果 ⊆ 静态版的 `audit` 结果(采样不该引进新缺陷)。

## 方向清单(按"证据 × 成本"排, 不是按大小)

### P0 · 地基(不做, 后面全悬)

- **`TIMING` 单一真值表**, 对称 `EASING_SPLINES` 的写法: 蚂蚁线 / 节点脉冲 / stagger 步长 /
  单趟走满的时长与延迟各收敛一处; 导出为纯数据 + 一个 `resolveTiming()` 纯函数(可逐项断言)。
  ⚠ 表内要分两类: **正确性常量**(缝重叠量这类)**不暴露**; **风格旋钮**(节拍快慢)**暴露可覆写** ——
  混在一起, 作者能配出"无重叠"的错觉参数。
- **相位归整 `snapToInt`**: 凡"第 k 拍 / 第 k 个"由除法反算的地方必须归整, 否则
  `floor(4.999…) = 4` 会让 golden 随机翻红(对账二第 3 条)。
- **`EASING_SPLINES` 的四值 ∈ [0,1] 守卫**(8 行): 现在 10 条全合规, 这条防"以后加错词"。
- **文档补齐**: `README.md` 的 descriptor 索引与 `QUICKREF.md` 至今没列 `animate()` / `style()` /
  `EASING_SPLINES` —— 已有能力没写在入口上, 等于没有。

### P1 · 声明式档的可用集(场景 A / C 的实际收益)

- **dash 工具**(吃 `Pt[]` 不吃 `d`): `polylineLength` / `pointAtLength` / `tangentAtLength` /
  `cutAtLength` + `dashDrawOn` / `dashFlow`。前缀和 + 二分 + 段内线性插值, 整数正交下是精确的。
  **余量纪律 `E = ceil1(L) + 1`**(对账二第 4 条)。
- **蚂蚁线根本不算长度**(固定 dasharray + offset 走一个周期) —— 这条主要成本是**写进 QUICKREF**,
  免得后来人先去做长度内核。
- **stagger helper**: 时间跨度 + 缓动压分布(不是索引 cap), 毫秒单位。
  ⚠ 现方案的 160ms × 12 = 1760ms 与 780ms 单程自相矛盾, **数要重定**。
- **`animateMotion`**(`DAnimate` 加一个 kind 分支): 语义 token 沿 authored 路径跑,
  `rotate="auto"` 比 dashoffset 更"信息性"(方向 + 语义种类同时表达)。
- **端点手艺写成判据**: 末帧精确落位(不是"差不多")、缝重叠只加后到者前缘、正确性常量私藏。
- **三档越界口径进 `constraints.ts` + `codes.ts`**: 作者声明矛盾 → 抛; 几何越界 → 退化成合法;
  被外框合法裁掉 → 钳。配套一个"时长账"检查(stagger 跨度 + 单趟时长 > 容器总时长要喊)。

### P2 · 效果与几何扩展(按真需求触发, 先探针后代码)

- **`feTurbulence` 探针**(半天, **零 src 改动**): 十变体 ×`rsvg-convert` + `qlmanage` 两路像素 diff,
  `diff < 0.1%` 才准进交付产物档。这是"声明式噪声"能不能用的**唯一判据来源**。
- **`DFilter` 槽 + 只开最稳的三个**(`chromatic-aberration` 教科书级 / `tint` 逐字等价 /
  `drop-shadow` 单原语)。**别一次开一堆** —— filter 的风险不在支持度, 在跨渲染器同形。
- **`starburst` 几何化**(N 楔 + `radialGradient` mask, 零 filter)、**手绘抖动件**
  (rougjs 的几何构造 + 常数, 用自己的 hash)。
- **弧 → 三次贝塞尔**(为"弧进谓词"备料: 弧与线段求交 / 点在圆角盒内)。
- **转场几何**(`clipPath` descriptor + wipe / clock-wipe / iris): 要有真需求才开, 它是 200-250 行级。

### P3 · 采样档 / 视频生成(待真需求与真宿主)

- `sampleAt(t)` 契约 + `tween` 原语 + 上面那三条不变量。
- **spring 离线烘焙器**(`scripts/`, 不进产物链): 形状归一化 + 非均匀 `keyTimes` + 压极值点采样。
  它同时是两条腿之间的桥 —— 烘出来的关键帧喂声明式档的 `values`。
- ⚠ **本场景对我的主要回报不是"更多动画能力", 而是给"字节确定"找到最强的外部需求方**:
  帧驱动渲染要并行渲不同帧到不同进程、同一帧可能重渲, 画面必须逐帧一致 —— 这**恰好等于**
  本仓的纯函数 + 量化纪律。所以这条路线的大部分工作是**验证既有纪律**, 不是新增功能。

### P4 · 交互档(场景 C)

- CSS 选择器通道已就绪(`ExportOptions.hooks`), 差的是**配方**: `:hover` / `:target` /
  `begin="click"` 的零 JS 交互写法进 `QUICKREF` + `templates`。

## 边界(哪些是能力边界, 哪些是选择)

**能力边界(做不到, 别再试)**: SVG 没有任意角度斜切(要自己算斜线与矩形求交)、
没有 `perspective` / `backface-visibility`(真 3D 翻转)、没有逐像素混合(11 个 WebGL 转场)、
没有"按块降采样"原语(pixelate)、没有 conic gradient(角度向羽化)、
`feBlend` 没有 `plus-lighter`(等权平均走 `feComposite arithmetic`)。

**选择(能做, 但刻意不做)**:

- **不做视频编码 / 帧序列 IO / 时间轴编辑器** —— 交给宿主。
- **内核不持有时钟** —— `t` 由消费侧给, 内核只做纯映射(与 `ROADMAP.md`「不做」里
  "播放状态机不进 core" 同一条线, 已焊死)。
- **不猜插值** —— 作者给什么就插什么, 内核不推"这里应该有个过渡"(P2 不猜意图的同族)。
- **不做"自动动起来"** —— 不识别"哪条边该跑马灯"、不给默认动效。与"不做自动排布"同款判词。
- **数字滚动类动画是踩线的, 要单独判** —— 它经过的中间态(`1234` 滚过 `1200`)可被读者读作数据,
  而 `docs/infograph-roadmap.md` 的立场是"**数必须是作者写的那个数**"。
  可接受的形态只有一种: **首帧是 0 / 占位, 末帧精确等于作者声明的真值, 中间不停留** ——
  即由 finite + settled 覆盖, 且末帧 = 静态值这条不变量必须过。
- **infinite 循环装饰不做** —— website 画廊同页多份内联, 无限动画是灾难。

## 待拍板(需要作者定, 定完才好动代码)

1. **`t` 的语义**: 内核统一收**毫秒**(与 `TIMING` 同单位), 还是收归一化 `0..1`?
   倾向毫秒 —— 归一化是场景侧的事, 而 `dur` / `begin` 本来就是 ms。
2. **`EASING_SPLINES` 存数还是存串**: 现在存字符串(声明式档直接吐), 采样档要用四位数值。
   两条路: 表改存**数值元组**(两腿都从它派生 = 更"一处事实", 但是 **L2/L3 破坏**, `EASING_SPLINES`
   是公共面)vs 加一个 `easingSplineTuple(name)` **解析函数**(L0 纯增量, 但字符串仍是真值)。
   倾向先走 L0, 两条腿都真用起来之后再评估改形态。
3. **stagger 的时间跨度默认值** —— 现方案的 160ms × 12 与 780ms 单程矛盾, 数要重定。
4. **第一个要动的真图是什么** —— 沿用"先有一张要动的真图"那条纪律, 没有它, 上面全部只算备料。
