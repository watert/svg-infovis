## 定位：这层补什么

手排实测（`examples/gallery/harness-arch.ts`）挖出的真问题：**三轮迭代只有一轮是门禁驱动的，另两轮全是"门禁说没事、看图发现是错的"**。硬门禁给的是 binary 判决（合法/非法），agent 摆完盒子后缺的是**梯度信号** —— "哪里可能丑、丑多少"。

本层就是补这个信号层。框架选型结论：**CRAP 只是入口词汇，不是框架本身** —— 它四条里真正属于结构图的只有一条半。骨架应该是**图可视化的实证美学**（有用眼动 / 任务完成时间实测的可读性因果链），CRAP / Gestalt / 栅格 / 信息设计分层挂在它周围。

**双阶段定位（前置比收尾更重要）**：本指引不只是收尾验证工具，更是**设计期的决策清单**。三条理由：① **成本不对称** —— 设计期改一个决策是改一句话，收尾期改是重排一片坐标（手排税本税），预防永远比拦截便宜；② **意图只能在设计期注入** —— 实验里 14 处痛点全落在分层/换序/分组/方向，这些决策全部发生在写第一个坐标**之前**，收尾度量量到的只是决策的后果；③ **前置产物 = 意图标注** —— 设计期写下的"三层 / 主路径是 X / 有意留白右侧"就是收尾期警示的**白名单**，度量不知道什么是"有意"，除非设计期写下来。两阶段用同一套词汇、不同句式：**前置提问式（无产物可量，只有意图可问），收尾断言式（有产物，度量说话）**。checklist 模式的原话即双阶段："生成前先通读一遍；生成后逐项自检"。

**与门禁的关系（铁律）**：

- **全部警示级，永不进 fail-closed** —— 既定纪律"启发式一律 warning"，把审美焊成硬门禁就是用错误否决正确
- **每条度量先过最小图测试** —— `long_edge` 在单边图上挂掉 9 个测试的教训：上线前先问"它在我最小的那张图上说什么"，假警报比漏报更快毁掉信用
- **验收口径**：自家真实产物（架构图 showcase / harness-arch）零假警报

## 目标函数选边（260922 定案）：可追踪性优先，交叉退第二序位

**这层要落地，先得回答"度量的'更优'朝哪边"** —— 生态里有两个**不兼容**的目标函数：

| | **可读性**（Purchase / Ware 一脉） | **可追踪性**（Mermaid 的实践） |
|---|---|---|
| 最疼的量 | **交叉数** —— 各项准则里对任务完成时间影响最大 | **折弯数** —— `BEND_PENALTY_4 = 5 > CROSSING_PENALTY = 3` |
| 背后的判断 | 眼动 / 任务实测：交叉破坏"这条线从哪到哪" | 一条没人看得懂的路径，比一张有交点的整洁图更糟 |
| 取向 | 宁可多两个弯，也要少一个交叉 | 宁可留一个交点，也要把路径拉直 |

⚠ **不能引 Mermaid 当背书** —— 它选的是**可追踪性**；我们若选可读性，它正好是**反例**而不是依据。

**我们的选边：可追踪性优先（trace-first）**。依据三条，全在本仓可查：

1. **图型分布以"沿线追一条路径"为主** —— 配方 1/2/3/6/9/10 是路径型（分层链路 / 时间线 / 依赖 / 判定流 / 序列 / 状态机）；关系密集型（4 fan-out / 5 矩阵 / 7 边形态 / 11 本体）是少数。
2. **既有硬门禁里"可追踪"已占多数** —— `no_backtrack` / `endpoint_approach` / `edge_overlap` / `port_crowding` 四条打的都是"这条线追不出来"；而交叉**只给数不判违例**（`crossings` 只进 `metrics`）。选边只是把一个已有的事实写明。
3. **判据原文就在 `QUICKREF.md`** —— fan-out 那一节写的唯一判据是"读者能不能沿线追出哪条进哪条出"。

**三个后果（一起认下来）**

- **① `route_rhythm` 的额度里折弯优先于交叉**：先按 ≤2 弯 / 拉伸比 ≤1.35 / 中段 ≥16px / 微段 <8px 落 **warning**，交叉只进 metrics。**不因此升 error**（启发式一律 warning，不动）。
- **② `routeCost` 的维度表行序与选边相反，放开新维度前必须先对齐**：现在 `crossingCount` 排在 `bendCount` **之前**（`src/knives/route-cost.ts` 的 `ROUTE_COST_DIMENSIONS`）。今天无产物影响（只启用 `backtrackPx` / `endpointBitePx` / `stretchMilli` 三维），但**放开新维度 = 让行序变成真审美** —— 那是放开前的第一件事（记入 `ROADMAP.md`）。
- **③ 选边是"默认序"，不是"唯一序"**：关系密集型图的读者换任务了（不是追路径，而是"哪个格子有 / 谁连谁"），那时交叉才是首序。需要时按图型**显式**换序 —— 但换序是作者决策，**core 不许自动判图型**（同"core 不猜意图"）。

**这一节没解决的那半（诚实记账）**：它让阈值不再是"拍的"，**但不等于校准过** —— 每条度量的数值门槛仍要在 ≥3 张真实图上量过才算数（见文末待修订清单）。

## 第一圈（骨架）：图可视化的实证美学

Purchase et al.（1997 起）与 Ware 的感知实验，按对可读性的实测影响排序。**每条都有实证 backing，不是设计师经验**：

1. **交叉数** —— 所有准则里影响最大。`metrics` 已有交叉计数，backing 最强
2. **弯折数** —— 边的 bend 越多越难追。可量：每边折点数分布、主路径 bend 总数
3. **流向一致性（continuity）** —— 主路径方向突变（先右后下又折回左上）最伤阅读。可量：相邻边方向变更次数。**回折门禁本质就是这条的硬底**
4. **边长均匀** —— 已有（长边相对基线）
5. **对称性** —— 影响弱且有争议，**别当度量**

本仓的门禁体系其实已在不自觉执行前两条 —— 修订时给每条度量补上实证出处。

## 第二圈：Gestalt 格式塔（CRAP 的底层，比 CRAP 更贴拓扑）

CRAP 的 P 本来就是 Gestalt proximity 的改写。其余各条的映射：

- **相似性（similarity）**：同语义类节点同形同色。可量半截：tone 使用是否聚类（同 tone 节点是否同组），随机撒 tone 即违背
- **连续性（good continuation）**：人眼自动追踪平滑路径 → 即第一圈的流向一致性
- **共同区域（common region）**：组框是它的实体化。可量：**孤儿节点** —— 组框内与组内其余节点零边连接的节点，有则说明分组是装饰不是语义
- **图形-背景（figure-ground）**：主路径 vs 辅助边应有视觉分层。可量：主链路边与交叉边是否同粗同深（该有别）

## 第三圈：CRAP（降级为组织词汇）

四条里真正属于结构图的只有一条半：

- **P 亲密性** —— ✅ 已有：`density` 三项（组内空白走廊 / 混组层 / 长边）收编；已把①从"面积比"换成"最大空白走廊"（两方向取宽 + 三闸: ≥48px 且 (占比 > 0.25 或 ≥ 节点尺度)）。⚠️ 换口径的**立项理由已修正**：8 张真图校准显示旧口径在真实层带型上并未系统性误报，收益实为"诊断可行动"
- **A 对齐** —— 🟠 有工具没度量：`nudge` 能修但没有信号。候选：同层 `centerY` / `centerX` 偏移 > 2px 计数；层归属由 agent 标 `band` 或 y 聚类推断（推断就标 heuristic）。修法闭环参照 `label_fit` 的 widen-node patch
- **R 重复** —— 🔴 空洞。候选：同层 `rect.h` 极差 / CV、相邻 gap CV、字号种类数 > 3 警示。注意：有意的主从结构会被误伤 → 只能警示级
- **C 对比** —— 🟡 天生残缺。可量半截：`solid` 数 > 2 警示（强调通胀）；全图零 solid 且有组框 → 弱警示。量不了的半截（"强调是否落在语义主角上"）留给 agent 自审 —— **承认残缺比假装能量重要**

## 第三圈半：版面设计体系（借半个）

- **栅格吸附率**（Müller-Brockmann）：正交锁定 + `snap` 已是隐性栅格。可量：x/y 坐标集中在少数几条"磁力线"上的比例 —— 与 A 互补：A 量同层对不齐，栅格量全局磁力线数
- **字号/字重阶梯**（借 checklist 模式：越大越细、同页小字字重 ≥ 大字）：结构图版 = 组框标题 > 节点标签 > 边标签，排序单调性可量
- **间距节奏**（8pt grid 思想）：gap 应为基准单位整数倍。比 R 的 CV 更严格、更可修（`snap` 直接给 patch 值）

## 第四圈：信息设计（借概念，别当度量）

- **Tufte 数据墨水比**：装饰墨水 / 信息墨水。极简 outline 天然占优 —— 定位是**防御性原则**，将来有人想加阴影渐变时拿出来挡
- **认知负荷（7±2）**：单层节点数 / 组内节点数 / 单节点出度上限。可量但阈值见仁见智，弱警示
- **留白节奏**（东方 negative space）：量的不是空白**总量**（density 已量）而是**分布** —— 大空白聚在一个角落是事故，均匀散布是呼吸。可量：画布分区空白率方差

## 不适用清单（与适用清单同等重要，免得后来者重新纠结）

- **三分法 / 黄金分割** —— 单焦点构图工具（照片 / 海报）；结构图是多焦点网络，没有"视觉中心"可放，硬套只会逼出畸形布局
- **对称性追求** —— 见第一圈第 5 条，实证上影响弱
- **色彩调和理论**（色环 / 互补色）—— 主题系统已把选色压成 7 tone 枚举，自由配色根本进不来，无需度量

## Checklist 攒法

格式：每条 = **现象 → 根因 → 做法 → 自检**，按 P0-P3 分级。**每条都必须来自真实踩坑，不许设计出来** —— 它是"前人的评审结论固化"，不是规范创作。

首批素材（手排实测，待补全细节后转正）：

- **P0 候选①**：直线横穿节点盒而门禁全绿（→ 已固化为穿盒门禁，转正后此条从 checklist 退役成门禁）
- **P0 候选②**：route 吐回折 / 自重叠折线（e5 越过再折回、e8 出 18px 原路退回）而无任何信号（→ 已固化为回折门禁）
- **P1 候选③**：层带型图上密度警示刷屏，agent 学会忽略警示（= 告警通胀，比没有警示更糟 → 已固化为密度警示）
- **P1 候选④**（架构图 v2 实跑）：**“把标题挪出组框”不等于“把标题挪出冲突区”** ——
  现象：`outer` 标题看似已在框外，主轴边照样从头穿过；门禁（`text_clearance`）抓到净空 0，
  但**通过门禁的修法（缩窄拉远）与版式意图无关**，是在为一条不该弯的线让路。
  根因：冲突区不是“组框内/外”，是“主轴 x ± 半宽”那条竖带——它跨组框内外。
  做法：先算主轴带的绝对 x 区间，再把标题（含字号）放进它某一侧的剩余宽度里；
  放了就不放，宁可换行/缩短/改放右侧注解轨。
  自检：标题包围盒与任一条主链边的 x 投影**完全不重叠**（不是“净空 > 0”，那是擦边通过）。

**退役机制**：一条 checklist 规则被固化成自动化度量 / 门禁后，从 checklist 划掉并注明去向 —— checklist 是度量层的**孵化器**，不是终点。

## 实跑记录（架构图 v2，首个真实案例）

对象：`refs/architecture-v2.svg`（改自 `build-arch.ts` → `build-arch-v2.ts`）。
走完全程：前置七问落字 → 手排 → 三次出图 → 收尾环五步。

**验证了的三件事**：

- **双阶段定位是对的** —— 三处实质改动全部发生在**写第一个坐标之前或同一轮内**；
  其中“主轴捋直”与“blink 降级为旁路”两个最大的收益，是前置七问第 1 / 第 4 问直接逼出来的（前置 > 收尾 ✓）
- **“门禁全绿 ≠ 看着对”又中了一次** —— 首跑 `0 error / 0 warning`，而右下角一整片空旷（告警看不见的东西）
- **白名单机制有用** —— 声明过的“主轴靠左”“组框标题字号小于节点标签”两条，收尾期直接豁免，
  没人为它们纠结（但本次并非靠它**压住**假警报，因为密度三项本来就安静 —— 这一项仍待验证）

**追加（同日 · 看图捉出，值得记）**：门禁全绿 ≠ **覆盖到位**。一眼能看出"文本压在节点盒上"，
而 ④`label_clearance` 与 ⑥`text_clearance` **都只拿文本与「边」比** —— 文本压节点盒 / 遮罩压节点 /
文本压组框线 / 两块文本互压，四类最显眼的事故全部放行（已固化成门禁⑭ `text_overlap`）。
与"门禁看不见的东西"同族，但方向相反：**不是阈值松，是根本没在看那个维度**。
排查这类缺口的方法不是调参数，是问一句"这个对象还能跟谁撞"然后**穷举配对** ——
边配了文本、文本配了边，却没人配"文本配盒子"。人眼补的正是这张配对表。

**没验证到的**：

- **密度三项 / 美学度量本身** —— 本次 `corridor_max=0.1(22px)`、`mixed_rows=0`、`long_edges=0` 全安静，
  没机会验证“警告 → 修法”闭环（不过这正是想要的结果：**真图不响**）
- **纵横比执念** —— 第 7 问原本答“深链竖图”，实际排下来是 688×756（≈0.91 近方形）：
  9 节点单列 + 两列旁注的**自然形状**就是方的，硬拉长只会把纵向呼吸撑散。
  → **第 7 问的验收口径应改成“纵横比配得上拓扑形状”，而不是“越竖越好”**
